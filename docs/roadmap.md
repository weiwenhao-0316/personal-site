## 一、愿景与定位

### 1.1 一句话定位

**haoriver.site 是一个以学习和个人使用为主的数字收纳空间：把外部收藏、学习笔记、资料和项目记录整理成自己的内容资产，并逐步形成“输入、整理、输出”的闭环。**

### 1.2 双重目标

| 目标 | 说明 | 优先级 |
|------|------|--------|
| 学习目标 | 通过真实产品掌握需求、设计、开发、测试、部署和运维的基本流程，为实习做准备 | 主目标 |
| 产品目标 | 把网站从学习型模板逐步打磨成边界清楚、可以稳定使用、能够对外展示的个人产品 | 次目标 |

### 1.3 当前现状诊断

| 维度 | 当前事实 | 主要差距 |
|------|------|------|
| 部署运维 | 已完成阿里云 ECS + 宝塔 + Nginx + FastAPI 部署 | 缺自动化发布、备份和监控；线上新代码仍需人工核验 |
| 数据存储 | Collection、Notes 已有 MySQL CRUD 代码；Library 使用 `localStorage`；Vault 和 Wallpaper 使用 `IndexedDB` | Notes 及收藏修复需要线上终验，Library/Vault 尚未上云 |
| 内容 | 页面、示例收藏、示例笔记和项目卡片已经存在 | 真实内容仍需持续补充，部分首页内容是静态配置 |
| 工程化 | 已有 `README.md`、`AGENTS.md`、产品规格、交接模板和开发流程 Skill | 自动化测试、Lint、CI/CD、鉴权和数据库备份未完成 |
| 安全 | API 暂无鉴权，Chat 暂无限流 | 公网接口可写，存在数据破坏和 AI 费用滥用风险 |
| 产品定义 | 第一版定位、页面职责和第一阶段范围已写入 `docs/product-spec.md` | 文档仍是草案，需通过实际使用继续收敛 |

- [x] C1 Collection 接入 MySQL：CRUD 和封面抓取代码完成，线上最终状态仍需抽查

### 阶段 D：产品体验升级

- [ ] D1 首页内容真实化：展示当前阶段、最近更新和核心入口

- [ ] E4 CI/CD：GitHub Actions 至少执行构建和基础检查；生产发布仍需明确授权
- [ ] E5 监控告警：站点可用性、API 健康状态和服务器资源

## 四、协作方式：任务卡模式

每次迭代 = 一张任务卡，格式固定：

```text
【任务卡 #N】标题
所属阶段：A / B / C / D / E
要解决的问题：
功能目标：
学习目标：
允许修改的文件：
明确不修改的内容：
实现要点：
完成标准：
验证命令或人工验收步骤：
部署权限：未明确授权前不得部署
完成后更新的文档：
```

执行规则：

1. 开始任务前先读取 `AGENTS.md` 和 `skills/project-development-workflow/SKILL.md`。
2. 先核对代码、文档和 Git 状态，再决定实现方式。
3. 一次只处理一张任务卡；新想法先记录，不自动插入当前任务。
4. 实现后必须构建、测试或人工验收，并区分“代码完成”和“部署已验证”。
5. 有实际里程碑时更新路线图和交接文档。

## 七、明确暂缓的想法

以下方向可以保留，但在第一阶段闭环验收前不进入当前开发任务：

- Library 全量上云和大文件对象存储；
- Vault 自动分类、AI 摘要和批量处理；
- 完整多用户账号体系和复杂权限；
- Projects 后台化、复杂搜索、推荐和统计；
- Docker、微服务等与当前规模不匹配的架构扩展。

暂缓不等于否定。等核心内容流稳定后，再依据真实使用频率和学习目标重新排序。
