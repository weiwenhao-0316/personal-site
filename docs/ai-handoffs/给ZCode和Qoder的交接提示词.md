# 给 ZCode / Qoder 的项目交接提示词

请根据你能看到的当前项目代码、项目文档，以及你与用户在本次项目中的历史对话，生成一份“项目状态交接文档”。

## 目标

让另一位 AI 助手能够在不重新询问大量背景、不重复已经完成的工作的情况下，准确理解这个项目目前已经完成什么、正在做什么、还缺什么，以及下一步应该优先做什么。

## 项目背景

- 项目：`haoriver.site` 个人网站
- 技术栈：Vue 3 + Vite + Vue Router，FastAPI，MySQL，DeepSeek OpenAI 兼容接口
- 部署：阿里云 ECS + 宝塔面板，Nginx 托管前端并反向代理 `/api`
- 项目目录：`D:\claude test\personal-site`
- 主要文档：`AGENTS.md`、`AI开发提示词.md`、`交接文档-给同事.md`、`网站架构设计文档.md`、`docs/roadmap.md`、`docs/learning-progress-summary.md`

## 你需要完成的工作

1. 先检查当前项目目录、Git 状态、前后端入口、路由、composables、后端 API、数据库迁移文档和部署文档。
2. 回顾你与用户在本项目中的相关历史对话，提取已经确认的需求、设计决策、实际完成的修改、遇到的问题和用户明确推迟的事项。
3. 将“对话中声称完成的内容”和“当前代码中实际存在的内容”进行对照。
4. 标出文档与代码不一致的地方，不要擅自猜测哪个版本是正确的。
5. 给出当前项目的真实进度和建议的下一步，但不要修改任何代码、配置、数据库或部署环境。

## 必须覆盖的内容

### 1. 项目定位与当前目标

- 当前项目想解决什么问题
- 目标用户是谁
- 当前优先级最高的产品目标是什么
- 用户目前更偏向学习型项目、个人生产工具，还是对外展示产品

### 2. 已完成内容

按模块列出已经完成的功能，并注明证据来源：

- 前端页面和路由
- 收藏、笔记、资料库、仓库、项目、AI 助手
- 前后端 API
- 数据库表和迁移
- 本地存储、MySQL、IndexedDB 等数据存储
- 部署、域名、Nginx、SSL、宝塔配置
- 最近一次已经完成的视觉或交互改造

每一项尽量写出对应文件路径、接口路径或文档章节。

### 3. 当前进度

请把进度分成以下三类：

- 已完成：代码和文档都能证明已经完成
- 进行中：已经开始，但还没有达到完成标准
- 未开始或待确认：文档规划了，但代码中还没有实现，或者需要用户决定

如果可以，请按“阶段 / 任务 / 状态 / 证据 / 完成标准”整理成表格，并给出一个谨慎的整体进度判断。不要为了生成百分比而虚构精确数字。

### 4. 最近工作记录

列出最近几次重要工作：

- 做了什么
- 为什么做
- 修改了哪些文件
- 修改后验证了什么
- 是否已经部署到线上
- 是否还需要用户手动操作

如果只能从代码推断，必须明确写“根据代码推断”，不要把推断写成历史事实。

### 5. 未完成事项和技术债

至少检查这些方面：

- 鉴权和权限
- 数据存储是否统一
- 数据库迁移和备份
- API 输入校验、错误处理和限流
- 文件上传和对象存储
- AI 调用的费用控制和流式协议
- 前端加载态、错误态和异步操作
- 测试、Lint、CI/CD、日志和监控
- 生产部署用户权限和依赖版本

请按 P0 / P1 / P2 排优先级，并说明风险和建议完成标准。

### 6. 已知问题和失败尝试

记录已经遇到过的报错、根因、解决办法和仍未解决的问题。不要只写“已修复”，要说明修复后的验证方式。

### 7. 下一步建议

给出最多 5 个下一步任务，按优先级排序。每个任务必须包含：

- 任务名称
- 任务目标
- 为什么现在做
- 涉及文件或模块
- 完成验收标准
- 是否需要用户确认

优先选择边界清楚、可以验证的任务，不要提出一次性重写整个项目。

## 强制约束

- 不要修改项目文件，不要运行部署命令，不要提交 Git，不要推送远程仓库。
- 不要执行删除、重置、覆盖数据库或覆盖用户文件的操作。
- 不要把 `.env`、API Key、数据库密码、Token、SSH 密钥或其他敏感信息写入交接文档。
- 可以写配置项名称，但敏感值统一写成“已配置，未展示”。
- 不要把没有证据的内容写成已完成。
- 如果历史对话不可访问，要明确写出“无法读取该部分历史对话”，不要编造。
- 如果代码、文档和历史对话互相矛盾，分别列出三者的说法，并把矛盾交给后续 AI 判断。
- 使用简体中文，代码、命令、接口、文件路径和技术名称保持原文。
- 文档应面向接手项目的工程师，不要写成宣传文案，也不要加入空泛的鼓励内容。

## 输出位置

请将最终交接文档保存到当前项目的：

```text
docs/ai-handoffs/<agent>-handoff.md
```

其中 `<agent>` 必须替换为你的名称：

- ZCode 使用 `docs/ai-handoffs/zcode-handoff.md`
- Qoder 使用 `docs/ai-handoffs/qoder-handoff.md`

如果目标文件已经存在，先读取并在保留历史记录的前提下更新，不要静默覆盖已有内容。可以在文档开头增加“本次更新日期”和“本次更新摘要”。

## 交接文档结尾必须包含

```markdown
## 交接结论

- 当前项目阶段：
- 当前最重要的未完成事项：
- 下一位 AI 应先做什么：
- 仍需用户确认的问题：
- 本文档最后核对时间：YYYY-MM-DD
```

完成后只需告诉用户：交接文档已经写入哪个完整路径，以及其中是否存在无法确认的内容。
